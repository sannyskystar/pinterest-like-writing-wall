# A Field Guide to Technical Explaining

Good technical writing is not about sounding smart. It is about being kind to a future reader who is tired.

## Three moves

### 1. Name the invisible

Before you explain the tool, explain the problem it quietly solves.

### 2. Show the shape, then the details

Start with a 30-second mental model. Then layer.

### 3. Use the reader's words

Jargon is a shortcut for insiders and a wall for everyone else. Define it once, then use plain language.

[Abstract editorial diagram](https://images.unsplash.com/photo-1551288049-bebda4e38f71?w=800&q=80&auto=format&fit=crop)

Code examples should be the smallest thing that still works.

```js
// explain by example
function explain(topic) {
  return clarify(topic).withKindness();
}
```

If you can teach it, you understand it.
